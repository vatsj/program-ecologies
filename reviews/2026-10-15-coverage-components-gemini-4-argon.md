# Review of `specs/2026-10-15-coverage-components.md` by gemini-4-argon

1. **Design flaws or confounds:**
- **Path-dependent dynamic definitions:** Component (a) ("paths a program never meets in its own encounters") and (b) ("a second script for a set the lack rule treats as already held") are trajectory-dependent if defined dynamically, making static pre-run masks impossible. If defined statically, (a) and (b) are ill-specified. **Fix:** Define (a)–(d) strictly as static syntactic/semantic properties of `(program, script)` pairs in `notes/coverage-components.md` §1 before running. Specifically: (a) scripts for check-sets only queried by *other* roles' probes (off-role/off-equilibrium branches), and (b) scripts beyond the canonical first-synthesized one per lack-set.
- **Mask non-orthogonality and interaction with S₃:** In `minus-one` cells, if you strip component $X$ from the granted list, $S_3$ production might still synthesize part of $X$ at runtime (especially for (a) if an encounter eventually triggers it, or (b) if the canonical script wasn't granted). Conversely, in `plus-one` cells, granting (b) ("second paths") when the *first* path isn't yet held makes the grant act as a first path, confounding (b) with (a). **Fix:** Make (a)–(d) a strict static partition of $H \setminus S_3^{\text{static}}$ (where $S_3^{\text{static}}$ is what $S_3$ can ever produce on-path), or explicitly forbid $S_3$ from producing masked-out components in `minus` cells.
- **`invariant-key` mark confound:** The brief enables the `invariant-key` mark for cost. If this mark caches "unproducible" across encounters when an opponent lacks a script, it may freeze out $S_3$ production in `plus-one` cells once a partner Later acquires a script. **Fix:** Verify in `test_coverage_components.py` that the empty/full masks with `invariant-key` on match the un-marked $S_3$ and $H$ trajectories draw-for-draw on 2 seeds.

2. **Predictions that are wrong:**
- **Prediction 2 (that (b) second paths matter little) is likely wrong for `plus (a)` alone:** In the 3-player game, a concession boss probes two worker slots. If the lack rule marks a check-set as "held" after writing a script that only satisfies one partner's call skeleton, the missing second script (b) will block the 3-way handshake even when (a) is granted. **My prediction:** `minus (a)` $\le 0.05$ holds, but `plus (a)` alone will be $\le 0.10$; recovering $\ge 0.25$ will require `plus (a)+(b)` (both untravelled probe branches and full skeleton coverage per lack-set).

3. **Missing controls or cheap additions:**
- **Static Partition Verification (`S₃ + (a)∪(b)∪(c)∪(d) == H-full`):** Since (a)–(d) can overlap, `minus-one` and `plus-one` can all fail if regrowth requires a conjunction (e.g., (a) and (b)). Add a test or cell checking that the union of the four static masks equals $H$, and include a `plus (a)+(b)` cell (production rules together) vs `plus (c)+(d)` (provenance rules together). This directly answers the brief's framing question ("production rule vs. provenance rule") even if singletons fail.
- **Newborn vs. Founder grant split:** The brief grants masks to "founders and newborns" (with $mN=1$, "newborns" means migrants or copies). Since "Legibility at founding" already showed founding lists alone give 0/20 under $S_3$, clarify that "newborns" means *every* individual present gets the static mask on its own source's $H$-list, which is equivalent to changing the oracle/production rule rather than seeding.

4. **Alternative explanations not ruled out:**
- **Timing / Chicken-and-egg in 3-player encounters:** $H$-full gives scripts at $t=0$ of an encounter. $S_3$ produces scripts *after* a failed/unverified encounter. If fair bosses die by demography during the 1-encounter delay it takes for two militants to each produce their certificates against the boss, then `plus (a)` works simply because it **pre-populates** the script before the first encounter, not because $S_3$ *cannot* travel that path. **Fix:** In `runs/coverage-components.md`, log whether the granted (a) scripts used in the first fair encounter would have been triggered and produced by $S_3$ on that exact encounter +1 step.
